# Day 76 — Evidence Quality Summary Quality Gate Validation Report Export Validation

## Objective

Day 76 validates the exported validation report generated by Day 75.

The validation ensures that an exported report contains the required fields,
valid data types, supported status values, and internally consistent values.

## Files

### Implementation

`evaluation/evidence_quality_summary_quality_gate_validation_report_export_validation.py`

### Tests

`tests/test_day76_evidence_quality_summary_quality_gate_validation_report_export_validation.py`

## Validation Layers

### Structure Validation

Checks that the exported report contains:

- `quality_gate`
- `valid`
- `status`
- `errors`

### Value Validation

Checks:

- `quality_gate` is a dictionary
- `valid` is a boolean
- `status` is either `PASS` or `FAIL`
- `errors` is a list

### Consistency Validation

Checks:

- `valid=True` corresponds to `status=PASS`
- `valid=False` corresponds to `status=FAIL`
- valid reports do not contain validation errors
- invalid reports contain errors
- the embedded quality-gate record has a consistent status

## Important Semantic Distinction

The validation report describes whether the quality-gate record itself is
valid.

Therefore, a quality gate can legitimately contain:

- `valid=False`
- `status=FAIL`
- `accepted=False`

while the exported validation report can contain:

- `valid=True`
- `status=PASS`
- `errors=[]`

This means the quality-gate decision is FAIL, but the quality-gate record is
correctly structured and internally consistent.
